# Аудит окружения и проекта

Дата: 2026-10-02. Вход: предоставленный `VAD-main.zip` и `prompt_for_GPT`.

## Что было в архиве

- Android/Kotlin-приложение, один модуль `app`, foreground microphone service.
- PCM16 / mono / 16000 Hz, окно 512 сэмплов (32 мс), Silero ONNX в assets.
- Порог VAD 0,5, pre-buffer 1024 мс, пауза 3/5/8/12 секунд.
- Лимит 10 минут уже присутствовал. Не было явной связи частей и статуса разбиения; после лимита запись снова проходила ветку ожидания речи.
- Шумоподавления/оценки качества/очищенных копий не было. Преобразование Short→Float использовало 32767, из-за чего −32768 выходило за диапазон −1.
- Два одинаковых FileProvider в manifest; сохранённый статус active мог пережить аварийное завершение процесса.
- WAV writer мог удалить существующий файл при совпадении имени. Метаданные при удалении и записи не имели общего механизма синхронизации.
- В `gradle.properties` был абсолютный Windows-путь к JDK. Фактический AGP — 9.1.1, в неиспользуемом каталоге версий — 9.4.1.
- Четыре исходных WAV: 7,232 / 4,704 / 7,072 / 2,944 секунды, все PCM16 mono 16 kHz. Они оставлены без изменений.

## Среда проверки

Linux x86_64, 9 логических CPU, Python 3.12.14. Изначально пригодного для запуска JDK и установленного Android SDK не было. Для проверки в отдельной рабочей папке подготовлены Temurin JDK 17.0.16+8, Gradle Wrapper 9.3.1 и Android SDK; зависимости загружены из официальных источников. TLS-проверка оставлена включённой, Java использовала системное хранилище доверенных сертификатов.

Конфигурация итогового приложения: AGP 9.1.1, compileSdk 37, targetSdk 35, minSdk 24, ONNX Runtime Android 1.27.0. Эти рабочие версии сохранены; массового обновления зависимостей не выполнялось. Версия приложения поднята до 0.2.0, versionCode 2.

Инструменты проверки, SDK, Gradle-кэши и локальные ключи не включены в исходники. В `artifacts/` находится готовый debug APK; модель и ресурсы берутся из оригинального проекта. Подробный результат команд — в `VALIDATION.md` и `validation/`.

## Принятые решения

1. Сохранить исходный PCM и применять DSP к производной копии, поскольку фильтрация меняет тембр и не должна необратимо менять обучающие данные.
2. Использовать обычный CPU DSP, без GPU, сервера, RNNoise-моделей и новых native-зависимостей.
3. Разбивать WAV строго по сэмплам, не останавливать микрофон на 10-й минуте.
4. Не включать аппаратное шумоподавление/AGC поверх RAW. Запрашивать UNPROCESSED при заявленной поддержке, иначе VOICE_RECOGNITION.
5. Не повышать targetSdk без проверки новых ограничений Android на физическом устройстве.

Официальные источники для решений:

- https://developer.android.com/media/platform/mediarecorder — UNPROCESSED и fallback VOICE_RECOGNITION.
- https://developer.android.com/reference/android/media/MediaRecorder.AudioSource — назначение аудиоисточников.
- https://developer.android.com/build/releases/agp-9-1-0-release-notes — совместимость AGP, Gradle, JDK и SDK.

Доступного Android-телефона/эмулятора с микрофоном не было. UI, фоновый режим конкретного производителя, расход батареи и качество звучания на телефоне требуют отдельной проверки.
